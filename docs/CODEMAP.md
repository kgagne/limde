# Code map

Where to look before searching: one line per thing you might change, with its files.
`path::Name` is a class, function, constant or section in that file. `scripts/check`
fails if a path or name here stops existing, so update this map in the same commit as
a change that moves, renames or adds something it lists. Keep it under 150 lines.

**Repo vs installed:** `./install` copies everything to `/usr/local` and `/etc/xdg`.
Repo edits do nothing on a machine until a reinstall (and a restart of what changed).
Files in `config/home` are starter copies, put in a home only when missing.

## Tinybar (the panel): `components/tinybar/`
Test: `python3 -m unittest discover -s components/tinybar/tests`. Installed by
`lib/install/78-tinybar.sh::step_tinybar`, started by `config/autostart.d/40-tinybar.sh`.
- **window, layout, clock** — panel window, widget order, clock format, CSS load: `components/tinybar/tinybar.py::TinyBar.do_activate`, `components/tinybar/tinybar.py::TinyBar.update_clock`; the row (tasks, centred clock, icons) is `components/tinybar/tinybar.py::PanelRow`. Trap: the `components/tinybar/tinybar` launcher preloads gtk4-layer-shell; run `tinybar.py` directly and it won't dock.
- **popover switching** — one click on another panel button while a popover is open closes it and opens that button's; pointing only outlines a button (filled while its popover is open), and the open button's tooltip is off: `components/tinybar/tinybar.py::PanelMenus`, `components/tinybar/tinybar.py::button_widgets`, registered by `components/tinybar/tinybar.py::open_below_panel`; while a popover is open the hand over other buttons is set on the popover's surface (`components/tinybar/tinybar.py::PanelMenus.update_cursor`, GTK leaves the arrow there); styles `.panel-menu > button:hover` in `components/appearance/templates/tinybar.css.in`. Trap: GTK closes an open popover on the press and the other button sees neither press nor release, only the pointer's enter and leave, so the button under the pointer at the close is the one clicked. Opening popovers on hover alone was tried and dropped (2026-11-03): on a laptop a popover reopened from a pointer event showed as open but never appeared.
- **calendar** — click the clock: a month `Gtk.Calendar` on today, Today button after browsing: `components/tinybar/tinybar.py::CalendarMenu`, `components/tinybar/tinybar.py::calendar_shows_today`. Trap: the clock is the button's label; `.panel-menu`'s negative margin keeps it where `PanelRow` centres it.
- **task list, windows** — buttons per app ID, click to focus, cycle, or minimise the focused only window; first app pinned left: `components/tinybar/tinybar.py::TinyBar.render_task_list`, `components/tinybar/tinybar.py::TinyBar.on_task_clicked`, `components/tinybar/tinybar.py::task_click_action`, `components/tinybar/tinybar.py::FIRST_APP_ID`. Long names end in "…" (`components/tinybar/tinybar.py::TASK_NAME_MAX_CHARS`), and shrink further so the list stops at the clock (`components/tinybar/tinybar.py::TaskStrip`). Right-click menu with Close: `components/tinybar/tinybar.py::TaskMenu`, `components/tinybar/tinybar.py::TinyBar.close_app_windows`. Trap: a button's icon and position are set once, when it is created.
- **window helper** — C helper on wlr-foreign-toplevel: JSON snapshots out, `activate|minimize|unminimize|close ID` in: `components/tinybar/toplevel-helper.c`, `components/tinybar/tinybar.py::TinyBar.send_toplevel_command`. Rebuild with `components/tinybar/build.sh`.
- **icons** — theme icons by desktop entry or StartupWMClass; status icons picked from indicator text: `components/tinybar/tinybar_icons.py::desktop_entry`, `components/tinybar/tinybar_icons.py::IconLibrary.status_name`. Trap: `components/tinybar/tinybar_icons.py::StatusIndicator.set_text` picks the icon from its first argument, a state string ("VOL MUTED"), and shows its words after the first as the panel value (unless `display_text=`), or all of it when the icon is missing; the hover words go in `tooltip=`.
- **tooltips** — plain hover words, one function per widget: `components/tinybar/tinybar.py::network_tooltip`, `components/tinybar/tinybar.py::volume_tooltip`, `components/tinybar/tinybar.py::brightness_tooltip`, `components/tinybar/tinybar.py::battery_tooltip`, `components/tinybar/tinybar.py::notification_tooltip`, `components/tinybar/tinybar.py::task_tooltip`, `components/tinybar/tinybar.py::tailscale_view`; wording rules in `docs/UI-RULES.md`. Trap: to see one in the VM, move the pointer with QMP `input-send-event` abs events and no button (the scaling is in `tests/vm/vm::cmd_click`); the system menu's "Settings" is set inline.
- **wifi menu** — status, nearby list, join form, Disconnect/Forget, on/off switch: `components/tinybar/tinybar.py::NetworkMenu`, `components/tinybar/tinybar.py::NetworkMenu.on_network_clicked`, `components/tinybar/tinybar.py::NetworkMenu.rebuild`. Trap: the panel takes the keyboard (ON_DEMAND) only while this popover is open.
- **wifi join, NetworkManager** — D-Bus calls with no widgets, security and password helpers: `components/tinybar/tinybar.py::WifiControl`, `components/tinybar/tinybar.py::WifiControl.watch`, `components/tinybar/tinybar.py::wifi_security`. Trap: new networks are added in memory and saved only once connected; a wrong password shows only in the device's state reason (`device_failure`).
- **sign-in pages (captive portal)** — NetworkManager's `Connectivity` (PORTAL) read into the Wi-Fi state, "Sign in to the network" row, "sign-in needed" in the tooltip, one notification per network: `components/tinybar/tinybar.py::portal_url`, `components/tinybar/tinybar.py::portal_notice`, `components/tinybar/tinybar.py::NetworkMenu.notice_portal`, `components/tinybar/tinybar.py::NetworkMenu.open_portal`; notifications with a click action go through `components/tinybar/tinybar.py::post_notification`. Trap: PORTAL needs NetworkManager's connectivity check (`packages/runtime.list` installs Ubuntu's config for it); without it Connectivity is FULL whenever connected. In the VM, a `[connectivity] uri=` pointing at a local server that redirects fakes a portal.
- **bluetooth menu** — paired devices, Connect/Disconnect/Forget, "Pair new device" search, pairing questions under a row, on/off switch: `components/tinybar/tinybar.py::BluetoothMenu`, `components/tinybar/tinybar.py::BluetoothMenu.on_request`, `components/tinybar/tinybar.py::bluetooth_devices`, `components/tinybar/tinybar.py::BluetoothMenu.done_for`, `components/tinybar/tinybar.py::bluetooth_lists_to_fill`. Trap: hidden unless BlueZ runs with an adapter (setting `bluetooth`); only the first adapter is shown. An action's result reaches only the form it started from, and the switch follows BlueZ's signals, not its replies (which come first).
- **bluetooth, BlueZ** — D-Bus calls with no widgets, the object tree kept from signals, and the pairing agent (DisplayYesNo): `components/tinybar/tinybar.py::BluetoothControl`, `components/tinybar/tinybar.py::apply_bluez_signal`, `components/tinybar/tinybar.py::BluetoothControl.on_agent_call`; packages `packages/optional/bluetooth.list`. Trap: the agent answers only for the device being paired from the popover and refuses typed PINs ("Other device…" opens bluetoothctl).
- **tailscale** — on/off button, status every 10 s: `components/tinybar/tinybar.py::TailscaleButton`, `components/tinybar/tinybar.py::tailscale_view`. Trap: needs the user set as Tailscale's operator; `up` has no `--timeout` on purpose.
- **volume** — keys run `components/tinybar/tinybar-volume` (wpctl), which writes a state file Tinybar watches: `components/tinybar/tinybar.py::TinyBar.setup_volume_monitor`, `components/tinybar/tinybar.py::TinyBar.update_volume_from_state`. Popover (mute, slider, outputs; then the default microphone's mute, level and, with several, the list, hidden without one) and a `pw-dump --monitor` child for changes made elsewhere: `components/tinybar/tinybar.py::VolumeMenu`, `components/tinybar/tinybar.py::LevelControls`, `components/tinybar/tinybar.py::apply_audio_objects`, `components/tinybar/tinybar.py::audio_inputs`. The mic-mute key writes its own file: `components/tinybar/tinybar.py::MICROPHONE_STATE`. Trap: only a state file ending in a `key` line (the keys' writes) shows the level overlay; the panel icon never shows the microphone; its tooltip names it only while muted. Never act on `@DEFAULT_AUDIO_SOURCE@` unchecked: with no microphone it can be an output's monitor, which wpctl resolves to the output (`components/tinybar/tinybar.py::default_microphone`).
- **brightness** — `components/tinybar/tinybar-brightness` steps 10 % (1 % below 10 %, never 0) or `set PERCENT`; Tinybar watches sysfs: `components/tinybar/tinybar.py::TinyBar.update_brightness`. Popover slider runs `set`: `components/tinybar/tinybar.py::BrightnessMenu`, sharing `components/tinybar/tinybar.py::LevelSlider` with volume. Trap: brightnessctl comes only with the optional `packages/optional/laptop.list` (the slider greys out without it); `TINYBAR_BACKLIGHT_DIR` and `TINYBAR_BRIGHTNESSCTL` fake a backlight for tests and VMs.
- **level overlay** — the bar shown 1.5 s after a volume or brightness change: `components/tinybar/tinybar.py::LevelOverlay.show_level`. Trap: only the keys show it; the brightness slider's own changes are skipped by `components/tinybar/tinybar.py::brightness_change_announced`.
- **media keys** — volume, mic mute, brightness, screenshot keys: `config/labwc/rc.xml::keyboard`.
- **battery** — 5 s tick, time left, tooltip, load colour; plugged in but not charging (charge limit) shows `battery-plug` (state word `PLUG`, `components/tinybar/tinybar_icons.py::IconLibrary.status_name`): `components/tinybar/tinybar.py::TinyBar.update_battery`, `components/tinybar/tinybar.py::BATTERY_LOAD_LEVELS`. Trap: the load colours are `load_*` in `components/appearance/appearance.toml` (both palettes).
- **battery popover, charge limit** — state list above the graph, held/charging-to wording shared with the tooltip: `components/tinybar/tinybar.py::BatteryMenu.show_status`, `components/tinybar/tinybar.py::battery_rows`, `components/tinybar/tinybar.py::charge_limit_text`, `components/tinybar/tinybar.py::read_charge_limit`. Trap: `TINYBAR_BATTERY_DIR` fakes a battery (VMs have none); it is read once at start, its files every 5 s.
- **low-battery warning** — notifications at 10 % and 5 % (urgent), once per discharge: `components/tinybar/tinybar.py::battery_warning`, `components/tinybar/tinybar.py::BATTERY_LOW_PERCENT`, `components/tinybar/tinybar.py::TinyBar.send_battery_warning`. Trap: the once-only state is in memory, so a Tinybar restart below 10 % warns again.
- **power graph, history** — SQLite `~/.local/state/tinybar/history.sqlite`, 90 days: 5-minute `buckets` and raw `samples` (metrics read every 5 s or slower), written once per bucket; the graph's 7 days stay in memory: `components/tinybar/tinybar.py::HistoryStore`, `components/tinybar/tinybar.py::HISTORY_RETENTION_SECONDS`, `components/tinybar/tinybar.py::power_series`, `components/tinybar/tinybar.py::PowerGraph`. Test: `components/tinybar/tests/test_history.py`. Trap: `power_w` is recorded only on battery; empty bins mean mains. A restart within a bucket merges into the same row (upsert).
- **system menu** — cog at the right end: Appearance (light/dark), Power (Lock, Restart; Suspend, Log out, Power off under More); Log out, Restart and Power off ask for a second click: `components/tinybar/tinybar.py::SystemMenu`, `components/tinybar/tinybar.py::mode_switch_command`, `components/tinybar/tinybar.py::needs_second_click`, `components/tinybar/tinybar.py::CONFIRM_SECONDS`. Trap: Log out is `labwc --exit`, which needs the `LABWC_PID` labwc gives what it starts.
- **cpu, ram, temperature** — off in the panel (`SHOW_USAGE`), CPU and RAM rows in the battery popover: `components/tinybar/tinybar.py::TinyBar.update_usage`, `components/tinybar/tinybar.py::usage_rows`.
- **notifications** — bell, Mako over D-Bus every 2 s, per-row dismiss: `components/tinybar/tinybar.py::NotificationCenter`. Trap: Mako's history can't be cleared; dismissed rows are hidden in memory and return after a restart.
- **do not disturb** — the bell popover's switch sets Mako's mode, read back each refresh: `components/tinybar/tinybar.py::NotificationCenter.on_switch_set`, `components/tinybar/tinybar.py::DO_NOT_DISTURB_MODE`; the hiding is `[mode=do-not-disturb]` in `components/appearance/templates/mako.conf.in`. Trap: critical ones still show; the mode lives in Mako, so it ends with the session.
- **idle hide** — swayidle runs `components/tinybar/tinybar-idle`, which signals the pid file (USR1 hide, USR2 restore): `components/tinybar/tinybar.py::TinyBar.setup_idle_hide`, `components/tinybar/tinybar.py::idle_hide_order`. Trap: hidden windows are remembered in memory only.
- **settings** — optional `~/.config/tinybar/settings.toml`, read once at start: `components/tinybar/tinybar.py::load_settings`. Trap: broken TOML silently resets every setting.
- **panel style, sizes** — how big to make text, rows and controls: `docs/UI-RULES.md`. CSS in `components/appearance/templates/tinybar.css.in` (rendered to `~/.config/tinybar/style.css`; edit the template). Loaded at USER+1 priority so the user's GTK CSS can't restyle the panel.

## Installer: `install`, `lib/install/`
Test: `scripts/check`; `./install --plan` shows the plan without changing anything.
- **steps, order** — `install` sources each `lib/install/*.sh` (NN-name.sh) and calls the `step_*` functions in the list at its end; shared helpers in `lib/install/common.sh::changed`. Trap: order is that call list, not the file numbers. A second run must print "No changes".
- **packages** — `packages/runtime.list`, `packages/build.list`, optional groups in `packages/optional`: `lib/install/30-packages.sh::step_packages`, `lib/install/20-plan.sh::step_plan`. Trap: apt runs without recommends, so list anything only recommended.
- **labwc build** — release tag and commit pinned in `pins/labwc::LABWC_TAG`, `pins/labwc::LABWC_COMMIT`; built by `lib/install/60-labwc.sh::step_labwc`. Trap: rebuilds only when the stamp differs; a build must pass a headless `labwc -S true`.
- **other pins** — Walker/Elephant `pins/launcher::LAUNCHER_ASSETS`, PCManFM `pins/pcmanfm::PCMANFM_COMMIT`, `pins/firefox`. Trap: bump the Walker version together with its asset name, URL and sha256.
- **launcher config** — `config/home/.config/walker`, `config/home/.config/elephant`, started by `config/autostart.d/30-elephant.sh` and `config/autostart.d/50-launcher.sh`.
- **network** — switches netplan to NetworkManager and rolls back if it can't connect in 30 s: `lib/install/40-network.sh::step_network`, `lib/install/40-network.sh::nm_connected`.
- **login, tty1** — marked `~/.profile` block that execs labwc: `lib/install/50-session.sh::profile_block`.
- **session config** — `config/labwc` to `/etc/xdg/labwc`, autostart pieces, starter files, hidden apps: `lib/install/85-session-config.sh::step_session_config`, `config/hidden-apps.list`.
- **autostart** — `config/labwc/autostart` runs `config/autostart.d` pieces, then the user's; same name overrides, empty file disables. Trap: pieces are sourced into one shell; background long-running commands with `&`.
- **idle, lock** — 90 s idle hide, 5 min lock, 8 min screen off or suspend: `config/autostart.d/20-idle.sh::limde_lock`, `config/home/.config/swaylock/config`.
- **keys, touchpad, window rules** — `config/labwc/rc.xml::keyboard`, `config/labwc/rc.xml::libinput`, `config/labwc/rc.xml::windowRules`. Keys that move focus (Alt+Tab, Super+Return, Super+D, Alt+Space) run `walker --close` first: Walker keeps showing after losing the keyboard. Trap: a user's touchpad block replaces limDE's whole block, and a `--` inside an XML comment breaks the file (`scripts/check` parses it). Window corners and title fonts are fixed in rc.xml's `<theme>`, not the appearance settings.
- **default apps** — `config/home/.config/mimeapps.list` (starter file).
- **helper commands** — `lib/install/82-helpers.sh::step_helpers` installs a named list to `/usr/local/bin`. Trap: a new command needs a line here (Tinybar's in `step_tinybar`, listed in three loops).
- **updates** — `limde-update` fetches the newest release tag into the installed clone, shows notes and rebuilt pins, checks it out detached and runs `./install --yes --with=` the recorded groups: `components/updater/limde-update::choose`, `components/updater/limde-update::main`; record written by `lib/install/89-record.sh::step_record`. Test: `python3 components/updater/tests/test_limde_update.py`. Trap: test releases are offered only while the installed version is one (or untagged); the record's groups come from the last `./install` run.
- **scrub gate** — no personal or machine data in tracked files: `scripts/check`, `scripts/public-patterns`, `scripts/public-allow`, run by `.githooks/pre-commit`.

## VM tests: `tests/vm/` (needs KVM; details in `tests/vm/README.md`)
- **fast bench** — `tests/vm/vm::cmd_save` (installed image), `up NAME --installed`, `tests/vm/vm::cmd_sync` (working tree in, `./install`, reboot). Full install tests are a separate pass before a push (`tests/vm/README.md`).
- **vm tool** — `tests/vm/vm::cmd_base`, `tests/vm/vm::cmd_up`, `tests/vm/vm::cmd_copy`, `tests/vm/vm::cmd_shot`, `tests/vm/vm::cmd_click`. Trap: `copy` is `rsync --delete`; `click` assumes the same `LIMDE_VM_RES` as `up`.
- **install test** — `tests/vm/test-install NAME [--keep]`: two runs ("No changes"), reboot, session checks.
- **release check** — `tests/vm/test-acceptance` (about 40 min): power cut and Ctrl+C mid-install, first login, baseline, update over user changes.
- **wifi test** — `tests/vm/test-wifi NAME` after `test-install NAME --keep`: simulated radios, two hostapd networks, `tests/vm/wifi-check`. Trap: it tests the installed Tinybar, not the repo copy.
- **bluetooth test** — `tests/vm/test-bluetooth NAME [--keep]` on an installed VM: two virtual controllers from BlueZ's emulator (`btvirt`), `tests/vm/bluetooth-check`. Trap: Tinybar, as default agent, refuses the device side's pairing question; by hand, start `bluetooth-check --device` after Tinybar (`--keep` does).
- **logout test** — `tests/vm/test-logout NAME` on an installed VM: `labwc --exit`, then the new session has its own Elephant (`config/autostart.d/30-elephant.sh`). Trap: autologin returns within agent-web's 2 s check, so the old session lingers here; a typed password doesn't.
- **session-only actions** — polkit refuses NetworkManager control over SSH, so tests type into foot through QMP: `tests/vm/test-wifi::type_text`, `tests/vm/test-acceptance::key`. Trap: a Tinybar restarted over SSH is outside the session too, so its Wi-Fi joins and power actions are refused; reboot the VM instead. Only `tests/vm/vm` honours `LIMDE_VM_DIR`.
